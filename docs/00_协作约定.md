# 协作约定

> 目标：几个人同时改，仓库不乱、冲突少、谁改了什么一眼能看出来。

## 一、目录归属（谁动哪块）

| 目录 | 归属 | 说明 |
|---|---|---|
| `vision/` | 视觉负责人 | 方案、脚本、数据集配置；`report/` 是只读归档，不再改动 |
| `real_robot/` | 真机负责人 | 调试台后端/前端、动作链、示教与主从跟随 |
| `tools/` | 共用 | 真机排查脚本；谁写的谁维护 |
| `docs/` | 共用 | 协作约定与结论性文档 |

跨目录改动（比如视觉要改 `real_robot` 的接口）：先在群里说一声，别直接推。

## 二、分支与提交

- `main`：随时能跑，只接受 PR 或本人确认过的直接推送。
- 日常：`feat/vision-obb`、`fix/gripper-calib`、`exp/pose-tracking` 这类前缀 + 简短描述。
- 提交信息：`模块: 做了什么`，例如
  - `vision: 补 4 点单应求解`
  - `real_robot: 主从模式停止后保持使能`
  - `tools: 加主臂读取速率基准脚本`
- 一次提交只做一件事。调参刷屏的中间态不要提交。

## 三、视觉目录（重点）

`vision/` 已按队友习惯留好位置，只往这些地方放东西：

```
vision/
├─ 视觉方案.md          实际使用方案（唯一权威版本，改动走 PR）
├─ report/              报告素材，只读归档
├─ dataset/
│  ├─ data.yaml         类别定义
│  ├─ images/           ← 图片（不入库）
│  └─ labels/           ← 标注（不入库）
├─ weights/             ← 权重 *.pt（不入库，只留 .gitkeep）
└─ runs/                ← 训练输出（不入库）
```

**入库的只有代码、配置、标注规范、方案文档，以及 `report/` 下的素材。**
原始视频、图片集、`.pt`/`.onnx` 权重一律不进 Git（`.gitignore` 已挡）。
要共享权重：传网盘/对象存储，把链接写进 `vision/README.md`。

接口定稿（视觉 → 臂 的那条 JSON）以 [vision/视觉方案.md 第 9 节](../vision/视觉方案.md) 为准，
`real_robot` 侧照此实现，两边不再各说各话。

## 四、大文件红线

- 单文件 > 20 MB 不进 Git（GitHub 硬限 100 MB，超了历史也洗不掉）。
- 需要版本化的资产先问一句再加。
- 真要放二进制：用 Release 附件或网盘，仓库里只留 `.md` 链接。

## 五、上线前检查

1. 调试台能起（`cd real_robot\web && python server.py`），页面能读状态；
2. `python real_robot/web/test_leader_signlive.py` 通过；
3. 没有把 `runs/`、`logs/`、`cam_videos/`、`recordings/`、`.venv/`、`*.pt` 加进暂存区
   （`git status` 自己看一眼）；
4. 改了结论就同步改 `vision/视觉方案.md` 与 `report/`，别让文档和代码打架。
