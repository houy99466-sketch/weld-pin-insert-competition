## 逐页制作

### 1｜封面

- **屏幕**：上方写 BoHack 2026 和津兆机电企业命题。大字写 `kcahob`，项目标题里的「自进化」沿用亮绿。主视觉用 reBot B601-DM 和冲压工件。
- **口播**：「大家好，我们是 kcahob。同一个钣金件正放时能直接抓，侧放时夹爪可能够不到。我们做的是让机械臂看清楚，再决定要直接抓，还是先推正。」

### 2｜团队成员

- **屏幕**：侯宇杰｜中山大学 · 队长 · 有丰富机器人项目经验。马锐｜南开大学计算机学院。徐嘉睿｜北京航空航天大学博士。
- **口播**：「我是侯宇杰。接下来我们分两段讲：我的队友讲视觉，我讲机械臂控制和动作后的反馈。」队友的具体讲者在排练时确认。

### 3｜散乱工件如何送进焊接夹具

- **屏幕**：用四段工艺图呈现「散乱来料 → 抓取与整姿 → 放入焊接夹具 → 焊后取回」。在抓取与整姿下放同一工件的正放、侧放示意，用夹爪的接近方向说明为什么同一条轨迹不能通用。
- **口播**：「焊接可以自动做，但工件散乱来料时，还得由人判断怎么拿、怎么摆到夹具上。我们的重点是前段上料：先处理工件姿态，再把它按夹具要求放下。」焊后取回在工艺图中交代即可。
- **依据**：[BoHack 2026 赛道和赛题设置](https://tcnf5s7xd39g.feishu.cn/wiki/EpxXwbYkkieZrfk0QbRc7wWQnRc)

### 4｜视觉：从腕部画面识别工件

- **屏幕**：左侧用腕部深度相机装机图标出视角，右侧放一张 YOLO11 实际输出，标注本次画面能够提供的类别、姿态或角度。下面用三节点画「腕部相机 → YOLO11 → 工件观察」。
- **口播**：「深度相机装在腕部。YOLO11 视觉模块已经独立跑通，我们先从画面得到工件观察，给后续动作决策提供输入。」交回侯宇杰：「看清工件以后，机械臂还要决定下一步怎么动。」
- **制作依据**：YOLO11 的名称沿用团队路演口径。装机照片证明硬件安装，模型截图展示独立视觉输出。仓库的 YOLOv8s-seg 和 FoundationPose 数据归于各自实验，模型名称与实验截图应一一对应。手眼标定后如有连续成功记录，可补一帧从视觉输出到机械臂动作的对应画面。
- **素材**：[视觉实验方案归档](../vision/视觉方案.md)。腕部装机照和 YOLO11 输出图待补。

### 5｜控制：如何推正、抓取和放件

- **屏幕**：上排三张工件姿态卡。正放直接抓，侧放先推正，倒放先转到侧面再推正。需要推正的分支经过复拍，再汇入「抓取 → 抬升归正 → 定向放件」。页脚用短图注交代示教轨迹、逆运动学角度补偿、夹爪力矩反馈。
- **口播**：「正放直接抓。侧放或倒放，我们先用示教轨迹把工件推到容易抓的位置。抓的时候按角度修正夹爪，夹紧时看力矩反馈，再抬起来转回夹具需要的方向。」
- **素材**：[reBot B601-DM 调试记录](../real_robot/web/README.md) · [任务执行代码](../real_robot/web/chain_core.py)。首选三张实机动作帧，缺帧时用工件轮廓与箭头画示意。

### 6｜自进化设计：复拍后修正下一步

- **屏幕**：画一圈「观察工件 → 按姿态决定是否推正 → 推正后复拍 → 更新抓取判断」。旁边画出微调判定分支「当前观察 → Laya / System 1 判定 → 控制程序自动触发微调」。另用虚线画跨次设计方向「记录结果 → 汇总失败分支 → 更新动作规则 → 与上一版比较」，保留旧版供回退。
- **口播**：「推件会改变工件位置和角度。推完再看一次，才能用新的观察修正抓取。Laya 负责根据当前观察给出微调判定。控制程序读到「需要微调」后，自动触发机械臂的微调动作。跨次更新还要把抓取结果和重试记录留下来，才能比较策略调整前后的效果。」
- **模型标注**：PPT 用 **Laya**，讲者备注可记模型配置名 `laya-typed-decisions`。团队确认成功案例由控制程序读取 Laya 的微调判定后自动触发微调。竞赛手册关注两次运行比什么、系统更新了什么、怎么回退。复拍图讲的是单次任务中利用新观测纠偏，跨次更新的验证要看两次之间是否有系统依据结果做出的可追溯修改。
- **依据**：[BoHack 2026 选手手册](https://tcnf5s7xd39g.feishu.cn/wiki/RayEw7WXsiRSWQkHS5xctT8xn22?from=from_copylink) · [赛道和赛题设置](https://tcnf5s7xd39g.feishu.cn/wiki/EpxXwbYkkieZrfk0QbRc7wWQnRc)

### 7｜对照结果：一次未就位，一次完成放件

- **屏幕**：做左右对照。左侧取《失败.mp4》约 00:37 的终态，标「工件未保持在目标位置」。右侧取《堵头枪管装配.mp4》约 01:49，标「撤开夹爪后，工件保持就位」。两段画幅不同，分别等比放入同样大的区域，保留夹爪、工件和底座。
- **播放**：先用 5 秒解释观众要看的是夹爪离开后的结果。失败用 00:32–00:37.4，成功用 01:40–01:50，合计约 15 秒。剩余时间用两张静帧讲结果。是否采用并排同步播放，以两段的动作时机实际对齐为准。
- **口播**：「请看夹爪离开后的工件状态。左边这次工件没有保持就位，右边这次夹爪退出后工件保持在目标位置。」成功那次增加了 JEV 的微调判定：Laya 判定需要微调，控制程序读取该判定后自动触发微调，随后完成放件。
- **还需团队核对**：两次是否同一工件和初始姿态，除新增微调判定外，是否还调整了参数、示教点或动作规则，是否有对应的复拍与抓取姿态更新记录。对照画面展示放件结果，自动触发过程由团队确认。

## 报名表｜进化说明

### 1｜比较什么指标

实机对照比较单次放件结果。以夹爪撤离后工件是否保持在目标位置记分，未就位记 0，就位记 1。两段视频分别为 **0 和 1**，对应两次案例。作为视觉端补充，独立的 **YOLOv8s-seg 离线分割实验**在同一自动标注验证集上，首轮与选定微调权重的掩膜 mAP50 分别为 **0.515 和 0.695**。[选模记录](../vision/report/evidence/metal_video_annotations/yolo_model_selection.json)

### 2｜学到了什么

视觉端在实拍中观察到重复检测、漏检与掩膜边缘缺口，团队通过离线微调提高了预测掩膜与验证标签的一致性。实机端在两次演示之间加入了微调判定。团队确认第二次运行时，Laya 给出「需要微调」的判定，控制程序自动触发微调，随后完成放件。推正后复拍是任务内的纠偏设计，用新观察更新抓取判断。[视觉案例及实验记录](../vision/report/项目报告素材.md)

### 3｜坏了怎么回退

视觉模型若在同一验证口径下退化，回退方案是加载上一版分割权重，并用相同验证集复核。运行中若 RGB-D 跟踪偏离，现有视觉原型支持按 R 手动重定位。实机微调异常时，先停止当前动作并检查工件与夹具，再按回退方案恢复到加入微调判定之前的放件流程。现场可用的旧权重、控制回退入口及演示步骤待团队核对。[视觉重定位与状态记录](../vision/视觉方案.md)

### 填报与路演口径

- 表单若要求填写两次实机运行的单一指标，使用放件结果 **0 → 1**。mAP50 来自独立视觉实验，只随对应模型和验证条件引用。项目路演的视觉模块写 **YOLO11**，素材用对应运行的画面。
- 对照视频用于展示工件终态，自动触发微调由团队确认。两次的初始条件、是否复拍以及过程日志仍待复核。现有证据覆盖团队的离线模型迭代和运行时的自动微调，跨次自动更新策略仍标「设计方向」。
- 视觉重定位用于恢复当前跟踪，权重回退用于恢复上一版模型。控制回退在演示前确认具体入口和可恢复的版本。
