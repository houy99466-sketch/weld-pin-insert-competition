# reBot Arm B601-DM 调试前端

硬件：机械臂 → USB-CAN 驱动板 → USB-CDC 串口（默认 `COM21`）@ `921600` → 达妙 DM4340P ×3 + DM4310 ×4。

```
web/
├─ 启动调试台.cmd    双击即用（本机 python 3.14 + motorbridge 0.6.0）
├─ server.py        HTTP 后端：独占串口 / 跑动作链 / 状态 / 端口切换
├─ chain_core.py    执行层：Arm 封装 + FK + IK + PLAN（单一数据源）
├─ index.html       单页前端：按钮 / 关节表 / 侧视示意 / 计划表 / 日志
├─ home_pose.json   记录的「起始位」
└─ dh_extract.py    URDF→DH 反解（实验性，未定稿）
```

## 为什么要有后端

浏览器开不了串口，DM 的 USB-CAN 板是**独占** CDC 设备。`server.py` 独占 COM，网页只发 HTTP。
同一时刻只有一个程序能持串口：**调试台 / MotorBridge Studio(`ws_gateway`) / DM_Tools**。
两种失败分开报：被占用 → 提示 `taskkill /IM ws_gateway.exe /F`；找不到 → 列出系统现有串口。
页面有端口下拉（★ 标出像 DM CDC 板的口）+『切换端口』。

## 动作链 v3（`chain_core.PLAN`）

三段关键机制，都是被实机问题逼出来的：

1. **主运动用 IK，不用固定关节增量**
   关节增量只在某个起始姿态下才等于「前+上」；臂换个姿势后同一组增量会变成往后/往侧。
   现在 S3 给的是**臂自身坐标系的笛卡尔目标**（前 +35 mm / 侧 0 / 上 +105 mm），
   运行时用阻尼最小二乘 IK（数值雅可比，残差 ~1 mm）反解关节角。
   J1 是底座偏航，目标位移绕 z 反旋 q1 再送 IK，所以底座转到 85° 也一样「朝自己前方伸」。

2. **夹爪每次运行前现场标定**
   零点和机构状态会变（换件、重新校零、夹过东西），写死绝对角必然超程。
   `gripper_calibrate()` 以 0.6°/12ms 往正方向慢压，力矩 > 1.0 Nm 且位置跟得上 → 记「闭合端」；
   张开端 = 闭合端 −120°，释放位 = 闭合端 −60°，全部夹在 URDF 限位内。

3. **时长按真实行程算，卡滞只跳夹爪**
   上一步（含标定）会把关节挪走，所以每段开始都重新读位置再算时长：
   `dur = max(配置值, max|Δθ|/vlim × 1.25)`。夹爪段用专属判据（力矩 >6.5 Nm 或滞后 >25° 持续 0.4 s）
   判卡滞，**只跳过后续夹爪段**，臂的动作继续跑完，并在结果里标 `gripper_status: stalled`。

| 段 | 名称 | 目标 |
|---|---|---|
| S2 | 夹爪张开 | J7 → 标定的张开端 |
| S3 | 前伸 + 上抬 | IK：臂系 前 +35 / 侧 0 / 上 +105 mm（6 s 斜坡）|
| S4 | 夹爪闭合（轻夹） | J7 → 标定的闭合端 |
| S5 | 夹持保持 | 1.2 s |
| S6 | 夹爪张开（释放） | J7 → 闭合端 −60° |
| S7 | 回起始姿态 | 全部回起始位 |

位移一律**换算到臂系**报告（世界系会随 J1 转掉）：`displacement_mm.forward/lateral/up` 与 `world` 都给。

## 用法

1. 双击 `启动调试台.cmd`；2. 打开 <http://127.0.0.1:8765/>；3. 点 **▶ 复现动作链**。

| 按钮 | 作用 |
|---|---|
| ▶ 复现动作链 | 按 PLAN 跑（含夹爪标定）|
| ■ 急停 / 卸力矩 | 中止 + 失能 |
| 使能 / 失能 | 单独控使能 |
| 占用 / 释放串口 | 与 MotorBridge Studio、DM_Tools 交接 |
| 记录起始位 / 回起始位 | 存/回 `home_pose.json`（急停后恢复）|
| 幅度倍率 / 停在目标位 | 缩放笛卡尔位移、是否跳过回程 |

## 示教 / 录制 / 回放（teach & repeat）

流程：**开始示教录制 → 用手推着臂走 → 中途点『夹爪夹紧』→ 停止并保存 → 选中文件点『回放』**。

- **拖拽必须"按住"（deadman）**：只有按住页面上的『按住拖动』时设定值才跟随；
  松手/移开鼠标/窗口失焦立刻锁死。设定值相对起点还有 ±90° 硬上限。
  早期版本是"一直跟随"，结果把重力下垂误判成人在推，设定值一路往下放 → 臂自己越走越远（真实踩过）。
- **为什么不用力矩重力补偿**：这个 URDF 的惯量/零点和实机固件对不上 —— 模型算 J3 要 +7.19 Nm，
  实测保持力矩只有 −1.65 Nm（符号还相反），直接发力矩会把 7 Nm 砸出去。
- 参数：`TEACH_HZ=50`、死区 0.8°、跟随 0.35/拍、速度上限 1.2 rad/s；
  安全阈值：任一关节速度 >4 rad/s 或偏离起点 >150° → 立即退出示教。
- **夹爪**『夹紧』= 向闭合方向按 0.4°/拍（≈20°/s）爬，遇到力矩 >1.5 Nm 或滞后 >12°（卡住）或走满 60° 就停并保持；
  『张开』同理（遇阻 / 走满 110°）。夹爪动作会写成事件记进录制里。
- 录制内容：50 Hz 的 `[t, J1..J7]`，以及 `events`（夹紧/张开发生的时刻与角度），存 `recordings/teach_*.json`。
- 回放：先 3 s 平滑走到录制首帧，然后按原始时序逐点跟随（可传 `speed` 倍速）。
  夹爪角度也在录制里，所以"哪里夹住"会一起复现。

## 页面缓存 / 版本自检（踩过坑）

改完前端、浏览器还在跑旧 JS 时，症状是「页面能打开，但读不到状态、点按钮没反应」——旧页面根本不知道新接口。

- `index.html` 一律 `Cache-Control: no-store`
- 服务端把页面内容哈希注入 `const PAGE_VER`，并在 `/api/info.page_ver` 返回同一值
- 页面每次取信息都比对版本，不一致就**自动 reload 一次**
- 右上角 `页面 xxxxxxxx` 徽标可点 = 强制刷新

⚠️ 注入是**全局替换** `__PAGE_VER__`，所以 JS 里不能拿这个占位符字面量做比较
（曾写成 `PAGE_VER === "__PAGE_VER__"`，被替换成自己等于自己 → 判断恒真）。现在用 `/^[0-9a-f]{10}$/` 判断是否已注入。

## 主从示教：用另一台臂当"主臂"拖（2026-11-14 新增）

另一台 6 轴臂挂在 **COM22**（CH343 USB 转串口）上，总线是 6 个**飞特 Feetech STS3215**
总线舵机（`model=777`，ID 1..6），协议是 SCS 系列：`FF FF ID LEN INSTR PARAM... CHK`，
`PING=0x01`、`READ=0x02`（读位置：地址 `0x38`，2 字节）；波特率 **1,000,000 8N1**。
这 6 个舵机全部 `torque_en=0`（失能），所以**天生可以徒手拖**，正合适做主臂。

> 踩过的坑：这台臂上电后不主动发帧，必须主机轮询；一开始按 921600 扫是静默的，
> 换到 1M 才应答。另外 Windows 下 `serial.read(n)` 会等满 `n` 字节或超时，
> 用它收整帧会平白多花一整个 timeout（实测 60 ms → 5 Hz）；改成非阻塞轮询
> `in_waiting` 后 6 关节整轮读取到 **250~300 Hz**。

### 文件与接口
| 位置 | 作用 |
|---|---|
| `leader_scs.py` | 主臂只读驱动（扫描 / 读角 / 跨界展开）+ 映射 `LeaderMapper` + `leader_map.json` |
| `chain_core.leader_follow_loop()` | 主从示教主循环（读主臂 → 映射 → 限速下发 → 录制） |
| `server.py` | `GET /api/leader`、`POST /api/leader/open|close|map`，`POST /api/teach/start {"mode":"leader"}` |
| `index.html` 第 5 卡「主臂」 | 打开主臂 / 实时角度 / 每关节方向 / 开始主从示教 |
| `tools/probe_proto2.py`、`tools/scs_tool.py` | 现场排查工具（协议嗅探 / 舵机枚举） |

### 映射策略（两台臂 DH 不同也能用）
不做绝对角拷贝，做**相对增量**：

```
target_j = S0_j + sign_j · gain_j · (L_j − L0_j)      # 再夹到 URDF 限位、按 vlim·0.55 限速
```

- `L0 / S0` = 开跑瞬间主臂角 / 从臂实测角 → 一上手**不会突跳**；
- `sign` 每关节可翻转（界面里的「方向+」勾选框），`gain` 在 `leader_map.json` 里改；
- 单关节相对起点最大行程 130°（`max_travel_deg`）；
- 想改成"按行程比例绝对映射"：把 `leader_map.json` 的 `use_abs` 设 `true`，
  此时用每关节的 `lmin/lmax`（主臂舵机 EEPROM 限位）映射到 `smin/smax`（从臂 URDF 限位）。

### 安全行为
- 主臂**只读，永不上电**，不会自己动；
- 从臂使能前先按实测角下发一拍 `pos_vel`，避免 DM 电机"弹回上一次目标"（实测曾一次弹 5°）；
- 主臂掉线 >0.35 s / 从臂任一关节力矩 >15 Nm / 从臂滞后 >45° 持续 0.5 s → 立即退出；
- 停止示教时自动给从臂卸力；
- 录制格式与原来的示教完全一致（`[t, J1..J7]` + `events`，含 `leader_start` 记录 L0/S0），
  所以**回放、存槽位、任务链全都照旧**。

### 用法
1. 页面第 5 卡：端口填 `COM22` → **打开主臂**（右侧显示「已连 COM22 · xxx Hz」）；
2. 拖动主臂，看「主臂°/从臂目标°」两列是否合理；哪个关节方向反了就取消/勾上对应「方向+」；
3. 点 **开始主从跟随** —— 这只是"主臂映射模式"，从臂跟着动，**不录制、也不生成任何文件**；
4. 要录的时候点**同一个『开始示教』按钮**（顶部那个大按钮；跟随中它自动变成录制开关）：
   点一下开始攒样本 → 再点一下停止并立即落盘，**跟随不中断**，可以反复录多段；
5. 点 **停止主从跟随** 结束跟随（保持使能原地锁住，见下）；
6. 之后照旧「回放选中」或存进槽位做任务。

> 设计取舍：主从跟随 = 一种操作模式（主臂映射到从臂），不是录制动作。
> 录制入口只有『开始示教』一个，避免两个按钮抢语义。
> 实现上 `leader_follow_loop` 每拍检查 `ctl["record"]`：为真才 append 样本，
> 并在 `events` 里记 `record_start` / `record_stop`，所以文件里能看清录的是哪一段；
> 徒手示教（free/assist/follow）保持原样：开始即录制。

### 方向/增益改不动的问题（2026-11-14 修）**症状**：拖起来某个关节方向反了，点「方向+」勾选框，行为没变（配置写进去了，但运动不变）。
**原因**：`start_teach` 时把 `signs/gains` 拷进 `ctl`，循环里只读这份拷贝 → **运行中改映射不生效**，
必须停掉示教再开一次才吃到新值；界面上勾选框又被 250 ms 的轮询立刻回写成服务端状态，看着像"点了没用"。

**已修**（`chain_core.leader_follow_loop` + `index.html`）：
- 循环每拍从 `ctl["map"]`（就是 server 里那份 `leader_map`）读 `sign/gain`，**改完下一拍即生效**；
- 检测到方向变了 → 立刻以「当前主臂角 + 当前从臂角」为**新锚点重新锚定**，姿态不突跳、不甩；
- 前端：刚点过的勾选框 1.5 s 内不被轮询回写，并在日志里提示"松手即生效，已按当前姿态重新锚定"；
- 命令行兜底：`python leader_scs.py --map`（看当前方向）、`python leader_scs.py --flip 2`（翻转 J2）。

回归测试：`python real_robot/web/test_leader_signlive.py`（假主臂+假从臂，跑一半翻转 J2 的 sign，
断言"翻转前 J2 指令递增、翻转瞬间回到起点、翻转后递减"）→ 目前 PASS/PASS。

当前各关节方向：`J1..J6 = +, −, +, +, +, +`（J2 已按实测反向）。

### 主从模式下的夹爪 & 停止后不卸力（2026-11-14 修）
**症状 1**：主从示教时点「夹紧/张开」没反应。
**原因**：`leader_follow_loop` 当初没接夹爪状态机，`/api/grip` 转进来的 `grip_mode` 没人消费，
J7 只是被 `arm.enable()` 带着通电而已（而且当时只在 `j7_hold` 开了才下发指令）。
**修法**：把夹爪状态机抽成 `chain_core.grip_tick()`（闭合/张开的爬行速度、力矩阈值、
滞停判定、`grip_hold` 保压全部沿用徒手示教那套参数），主从循环每拍调用它并始终下发 J7 指令。
手感与徒手示教一致：夹紧 → 0.4°/拍爬行，力矩 >1.5 Nm 或滞后 >12° 或走满 300° 就停并保压；
张开 → 反向爬行，遇阻 >2.5 Nm 或走满 110° 停。

**症状 2**：停止录制时从臂突然失能、掉下去。
**原因**：`stop_teach` / 线程 finally 里对 leader 模式也调了 `arm.disable()`。
**修法**：leader 模式默认**保持使能**，停止时调 `core.hold_current()`（按实测角在 POS_VEL 上锁住 0.6 s）；
界面上新增勾选框 **「停止后保持使能（原地锁住，不卸力）」**（默认勾选），
`POST /api/teach/start {"mode":"leader","keep_enabled":false}` 可关掉它恢复旧行为。
`急停/卸力矩` 按钮仍然是真卸力，不受影响。

实测：停止后连续 3 s 采样 `status=1,1,1,1,1,1,1`，各关节角度零漂移（未修前同一测试里
J5 会掉 13°、J6 掉 7.5°）。
