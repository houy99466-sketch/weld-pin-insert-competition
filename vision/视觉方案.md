# 视觉方案（实际使用版）

> 一句话：**用 RealSense D435i 的 RGB-D + YOLOv8s-seg 实例掩膜 + CAD 模型，做"实例 → 二维方向 → 六自由度位姿 → 摆放状态"的四级输出**；YOLO 只负责分实例，几何和位姿不靠学习，靠 CAD 与深度。
>
> 状态：感知原型已跑通，四条链路的输出与指标都有落盘证据（[report/evidence/](report/evidence/)）。
> **尚未做**手眼标定、机器人坐标变换、抓取闭环——报告里不能写成"已完成自动抓取"。

## 1. 任务与输出定义

### 1.1 输入

| 输入 | 规格 | 必需性 |
|---|---|---|
| 彩色图 | 640×480，BGR，`rgb.png` / 视频流 | 必需 |
| 深度图 | 640×480，对齐到彩色视角，单位缩放 0.001 m | 6D 位姿必需 |
| 内参 | `cam_K.txt`（3×3），畸变全 0 | 6D 位姿必需 |
| CAD 网格 | `CT.obj`，米制，watertight | 6D 位姿必需 |
| 实例掩膜 | 与彩色同分辨率，单实例 | 初始化必需 |

> 普通 MP4 没有深度和内参，**不能**直接跑 RGB-D 初始化链路；只能走第 6 节的二维方向。

### 1.2 输出（三级，逐级可选）

```
① 实例层   掩膜 + bbox + 类别(CT/DT/TT) + 实例 id
② 角度层   二维方向（图像系模 90° / 掩膜长轴模 180°）
③ 位姿层   4×4 位姿矩阵（CAD→相机）+ 支撑面朝向（正放/侧放/立放/倾斜）+ 旋转角
```

### 1.3 坐标与单位约定（必须统一，否则后面全错）

| 项 | 约定 |
|---|---|
| 相机系 | x 向右、y 向下、z 向前（OpenCV 惯例） |
| 位姿矩阵 | `pose_object_to_camera`，**CAD 原坐标系 → 相机系** |
| CAD 平移 | 原 STEP 带装配偏移，**平移列不等于工件中心**；要中心就用网格包围盒中心重算（实测相机系 (-0.0130, 0.0249, 0.1874) m） |
| 长度单位 | 全部米制（STEP 毫米 → OBJ 米，`scale=0.001`） |
| 图像角 | 逆时针为正 |
| 位姿旋转正交性 | 实测 det=1.00000003，正交误差 6.95e-08 |

## 2. 总体流水线

```
                    ┌───────────── 离线（数据构建）─────────────┐
 视频 415~1759 帧 → 抽帧 → SAM2 关键帧提示传播 → 逐实例掩膜 → YOLO 伪标签 → 按整段视频分组
                    └──────────────────────────────────────────┘
                                     ↓
 ┌──────────────────────── 在线（单帧 / 视频流）────────────────────────┐
 │                                                                     │
 │  RGB ──► YOLOv8s-seg ──► 实例掩膜 ──┬──► 掩膜长轴 ──► 二维方向(模180°)│
 │                                     │                               │
 │  Depth + 内参 ──────────────────────┴──► FoundationPose 初始化       │
 │  CAD mesh ─────────────────────────────►        ↓                   │
 │                                          连续 track_one             │
 │                                                ↓                    │
 │                                     4×4 位姿 + 支撑面朝向 + 旋转角   │
 └─────────────────────────────────────────────────────────────────────┘
                                     ↓
                              给机械臂的 JSON（第 9 节）
```

**为什么这么分工**：学习只用在"把工件从背景里分出来"这一步（分割对光照、材质最稳）；
角度和位姿用几何（CAD 轮廓、深度、支撑面）算，误差可解释、可复算，也避免为姿势再训一套网络。

## 4. 数据构建（离线）

### 4.1 流程

1. **抽帧**：整段视频逐帧解码，不做跳帧（后续 SAM2 传播需要连续帧）。
2. **提示传播**：X-AnyLabeling 原生 **SegmentAnything2Video** 接口，关键帧框选 → 传播到全段。
3. **导出**：逐实例 PNG（保留模型原始掩膜）+ 多边形 JSON + YOLO TXT。
4. **转 YOLO 标签**：多边形填充成分割标签。
   ⚠️ 这一步会把掩膜的**内部孔洞填掉**（YOLO 多边形标签限制）；要孔洞就回看原始 PNG。
5. **分组划分**：**按整段视频分**，不按帧随机分——相邻帧几乎重复，随机会同时泄漏进训练和验证。

### 4.2 两套数据集（别混）

| | 旧：单类 CT | 新：混合三类 CT/DT/TT |
|---|---|---|
| 帧数 | 897（训练 585 / 验证 312） | **3,209**（训练 2,174 / 验证 1,035） |
| 实例 | 2,424（自动标注） | 见 `class_provenance.json` 逐视频对象表 |
| 来源 | `image/长条/` 三段视频 | `image/混合/` 1.mp4(415) / 2.mp4(1759) / 3.mp4(1035) |
| 划分 | 按整段视频 | 按整段视频：01/02 训练，03 验证（跨集重复 0） |
| 类别含义 | CT = 银白色支架 | **CT = 带法兰圆筒件**、DT = 方形孔件、TT = 银色折弯支架 |

> **同一个名字 CT，两组数据指的是不同零件。** 旧单类模型不能当新三类模型用。
> 证据：[class_provenance.json](report/evidence/mixed_video_annotations/class_provenance.json)、
> [split_integrity.json](report/evidence/mixed_video_annotations/split_integrity.json)

### 4.3 标注质量现状

- 全部是 **SAM2 自动伪标签**，未经逐帧人工验收；
- 825/897 帧带启发式复核提示（提示 ≠ 错误率）；
- GPU 峰值显存占用约 610 MiB（416×736 级别输入，够在 6 GB 卡上跑）。

## 5. 实例分割

### 5.1 模型与训练策略

| 项 | 值 |
|---|---|

| 首轮 | 32 epoch |

### 5.2 指标（对**自动标签**的一致性）

| 阶段 | 掩膜 mAP50 | 掩膜 mAP50-95 | box mAP50 | 掩膜 P | 掩膜 R |
|---|---:|---:|---:|---:|---:|
| 首轮（32 ep） | 0.515 | 0.282 | 0.560 | 0.691 | 0.511 |

[results.csv](report/evidence/runs/segment/metal_part_yolov8s_seg_refine/results.csv)

**读法**：这是"和自动标签有多一致"，不是人工验收准确率，也不是产线泛化能力。

### 5.3 已知失效模式（必须写进报告）

| 现象 | 影响 | 处置 |
|---|---|---|
| 同一长槽重复检测 | 实例数虚高 | 后处理按 IoU 去重 + 面积比过滤 |
| 中间折弯件漏检 | 少一件 | 多尺度输入 / 补样本；不能只靠置信度阈值 |
| 遮挡导致掩膜边缘缺口 | 位姿初值偏 | 初始化取最大且有足够有效深度的实例 |
| 外置 RGB 实时推理把屏幕/键盘当工件 | 误检 | 限定 ROI，或换工作区背景 |
| 预测数 = 实物数 | **仍是巧合，不等于实例一一对应** | 需人工抽查 |

## 6. 二维方向（两条支路）

### 6.1 支路 A：几何方向（不需要训练）

适用：已知工件是近方形/带孔件，只想拿"摆放朝向的模 90° 等价方向"。

| 步骤 | 做法 |
|---|---|
| 前景候选 | 暗物料阈值分割（背景 220 灰度，对比阈值 81~86） |
| 孔洞 | 椭圆拟合，判孔洞是否可分辨 |
| 边线 | LSD 直线检测 |
| 方向共识 | 正交方向投票（模 90°） |
| 拒识 | 目标截断 / 孔洞不可分辨 / 短边不足 / 正交支持不足 / 边方向不一致 |

**实测（415 帧、1280×720、13.84 s、29.99 fps）**：

| 项 | 值 |
|---|---|
| 逐帧候选观测 | 769 |
| 接受 | 339 |
| 至少一帧有有效角度的帧数 | 281 / 415 |
| 拒识主因 | 目标截断 315、孔洞不可分辨 55、短边不足 22、正交支持不足 28、边方向不一致 10 |
| 人工粗核对 6 帧的方向差 | 1.28° / 0.38° / **5.75°（超估不确定度 4.91°）** / 2.17° / 2.12° / 2.00° |
| 定义 | 图像水平方向模 90°，逆时针为正 |

证据：[summary.json](report/evidence/rotation_pose/video_results/all_visible/summary.json)

**边界**：模 90°，**不是**物理 yaw；无物理转角真值；B 目标出画后身份无法恢复，后面相似件不能接成同一轨迹。

### 6.2 支路 B：掩膜长轴（接在分割后面）

| 项 | 做法 |
|---|---|
| 取角 | 掩膜主轮廓的**最小面积旋转框**，取真实长边向量 |
| 周期 | **模 180°**（长边无方向性，分不出两个端点） |
| 拒识 | 小轮廓、近方形（长宽比不足）、截断、碎片 |
| 校验 | 对真实预测掩膜施加已知二维旋转，最大等变误差 **≈0.29°** |

**边界**：0.29° 只证明"算法计算正确"，**不是实物角度测量精度**；模 180° ≠ 桌面 yaw ≠ CAD 唯一朝向。

### 6.3 两条支路怎么选

| 场景 | 用哪条 | 理由 |
|---|---|---|
| 只有单目视频、要快速看朝向 | 支路 A | 无需模型，1 ms/帧 量级 |
| 已有分割模型、要跟实例绑定 | 支路 B | 角度和实例同源，不会串件 |
| 要真正的姿态 | 都不够，走第 8 节 6D | 二维投影天然丢一个自由度 |

## 7. 备用高精度通道：RGB 参考纹理旋转

在**同一参考物料、同视角**的强假设下，纹理法能做到亚度级；这是目前唯一有严格误差统计的通道，
但它的适用面很窄，**默认不启用**，只在"参考图能对上"时作为补充。

### 7.1 方法与阈值

RootSIFT 特征 → 多尺度参考（1.0 / 0.75 / 0.5）→ 双向匹配 → RANSAC 仿射 → 外观核验（NCC）→ 旋转极分解取角。

| 阈值 | 值 |
|---|---|
| `min_inliers` | 10 |
| `min_inlier_ratio` | 0.35 |
| `min_coverage` | 0.06 |
| `min_ncc` | 0.35 |
| Lowe `ratio` | 0.78 |

### 7.2 实测（700 正样本 / 88 负样本，同源合成）

| 指标 | 值 |
|---|---|
| 接受率 | 676/700 = **96.57%** |
| 已接受 MAE | **0.0619°** |
| 已接受 P95 | 0.2735° |
| 已接受最大误差 | 1.4723° |
| 负样本误接受 | **0/88** |
| CPU 单图中位耗时 | 188.8 ms |
| 最差族（复合干扰 combined） | 接受率 76%，MAE 0.269° |

对照几何基线：模 90°、接受率 92.57%、MAE 4.426°、**负样本误接受 60/88** —— 所以纹理法是主，几何法只做兜底。

证据：[metrics.json](report/evidence/rotation_pose/results/test/metrics.json)

### 7.3 真实迁移结果（关键的反面证据）

两张额外实拍图**全部拒识**，原因 `insufficient_geometric_support`：匹配 19/18 个，内点只有 4 个。

> 报告里必须同时写"合成测试 MAE 0.0619°"和"实拍两张均拒识"。只写前者就是误导。

证据：[real_transfer.json](report/evidence/rotation_pose/results/real_transfer.json)

## 8. 六自由度位姿（核心）

### 8.1 初始化（单帧，人工触发一次）

前置：同帧 `rgb.png` + `depth.png` + `cam_K.txt` + 单实例掩膜 + 正确 `depth_scale` + 匹配 CAD。

| 项 | 实测 |
|---|---|
| 选中实例 | `instance_id = 0`（前景最大实例） |
| 掩膜像素 / 有效深度像素 | 38,234 / 29,687（**77.6%**） |
| 深度分位（p10/p50/p90） | 0.169 / **0.176** / 0.184 m |
| CAD 模型深度范围 | 0.1657 ~ 0.2107 m |
| 初始化耗时 | ≈15.5 s（**含环境与模型加载**，不是每帧耗时） |
| 投影轮廓 IoU（三角面片剪影 vs 掩膜） | **0.9184** |
| 投影凸包 IoU | 0.8826 |

> IoU 0.918 是**同帧轮廓一致性**，不是 91.8% 位姿准确率。

证据：[initialization.json](report/evidence/ct_pose_capture/pose/initialization.json)、
[depth_quality.json](report/evidence/ct_pose_capture/depth_quality.json)、
[geometric_checks.json](report/evidence/ct_pose_capture/pose/geometric_checks.json)

### 8.2 连续跟踪

| 项 | 实测（tracking_01） |
|---|---|
| 帧数 | 150 |
| 总耗时 / 实际交付帧率 | 12.62 s / **14.50 Hz** |
| 单帧计算 中位 / P95 | **27.7 ms** / 33.3 ms |
| 末 50 帧中心标准差 | (0.73, 0.72, 1.10) mm |
| 末 50 帧中心极差 | (5.32, 3.79, 5.34) mm |
| 首末中心偏移 | (−0.34, +1.20, −3.59) mm |
| 精度验证 | `accuracy_verified: false` |

> 末 50 帧标准差小，但**期间物料在转动**——不能写成"静态定位精度 mm 级"。

### 8.3 支撑面、摆放状态与旋转角

| 量 | 算法 |
|---|---|
| 支撑面 | 用参考 RGB-D 中**工件之外**的区域拟合平面 |
| 摆放状态 | CAD 的 Z / Y / X 轴分别最接近法线 → 正放 / 侧放 / 立放 |
| 倾斜 | 最近轴偏离 > **25°** |
| 旋转角 | CAD 长边投影相对参考方向、在支撑面内的角度；长边接近法线时**不可定义** |

**边界**：这是**朝向分类**，不证明实际接触；不区分同轴翻面；相机或支撑面移动后必须重建参考。

### 8.4 重定位策略（已回退到手动）

- 当前：连续 `track_one`，**操作者按 R** 才触发分割 + 一次重新初始化；
- 正常跟踪**没有**自动丢失检测、**没有**自动恢复；
- R 会选择"完整且有效深度最大的实例"，多件场景可能切到别的对象；
- 曾实现自动重定位（轮廓 IoU + 深度一致性 + 失配判定 + 冷却），实测被反馈"重定位太频繁/效果不好"，**已移除**；
- `manual_only_verify` 的 90 帧验证：在第 30 次按键读取时由验证代码**注入一次 R**，成功且继续跟踪，中位 25.9 ms —— 这不等于人员实操验证，也不等于自动恢复能力。

证据：[tracking_01/summary.json](report/evidence/ct_pose_capture/tracking_01/summary.json)、
[manual_only_verify/summary.json](report/evidence/ct_pose_capture/manual_only_verify/summary.json)

```json
    "accuracy_verified": false
  }
}
```

### 字段状态（写代码时按这个来）

| 字段 | 状态 |
|---|---|
| `class` / `instance_id` / `conf` / `mask` | ✅ 已实现（YOLOv8s-seg） |
| `angle_2d_deg` / `angle_2d_period_deg` | ✅ 已实现（模 90 或模 180，看支路） |
| `pose_object_to_camera` / `center_camera_m` | ✅ 已实现（FoundationPose 跟踪输出） |
| `support_plane` / `orientation` / `tilt_deg` | ✅ 已实现（朝向分类；`tilt_deg` 为最近轴偏离） |
| `rotation_on_plane_deg` | ⚠️ 条件可定义：长边接近法线时为 `null` |
| `pose_in_robot_base` | ❌ **未实现**，需要先做手眼标定 |

**机械臂侧接入规则**：

1. 只吃 `pose_valid == true` 且 `quality.valid_depth_fraction > 0.5` 的帧；
2. `orientation` 只用来决定"要不要先翻面"，不要当成精确角度；
3. 任何 `null` 都要能被下游处理，不能当 0 用；
4. 位姿在相机系，**未经手眼标定不得直接下发给关节控制**。

## 10. 性能预算

| 环节 | 耗时 | 出处 |
|---|---|---|
| 分割推理（640，单帧） | 与 23 FPS 显示链路同量级 | 报告 §5 |
| 几何二维方向（支路 A） | ~1.06 ms/帧（纯 CPU 几何） | metrics.json（geometry.median_ms） |
| 纹理法旋转（支路 B 备选） | 188.8 ms/图（CPU 中位） | metrics.json（features.median_ms） |
| 位姿初始化 | ~15.5 s（含模型与引擎加载） | 报告 §5 |
| 位姿跟踪单帧 | **27.7 ms**（P95 33.3 ms） | tracking_01 |
| RGB-D 采集 | 15 FPS 配置 | camera.json + 报告 |

**端到端**：RGB-D 采集限制在 15 Hz，实测交付 **14.5 Hz**；计算耗时与吞吐**分开写**，不要用窗口 `track FPS` 冒充系统吞吐。

## 11. 失败模式与处置

| 失败 | 表现 | 处置 |
|---|---|---|
| 目标出画 | 身份无法恢复，相似件被接成同一轨迹 | 出画即判失效，要求重新挑选实例（不做自动接管） |
| 快速拿起 / 翻转 / 遮挡 | 三维框偏离工件，角度随之失效 | 判 `pose_valid=false`；人工按 R 重定位 |
| 相机或支撑面移动 | 支撑面参考失效 | 必须重建参考 RGB-D 与支撑面 |
| 多件同场 | R 可能切到别的实例 | 接口带 `instance_id`，上游锁定目标 |
| 掩膜孔洞被填 | 轮廓 IoU 虚高 | 需要孔洞时用原始 instance PNG |
| 深度缺失区大 | 初始化漂 | `valid_depth_fraction` 低于 0.5 直接拒 |
| 长期跟踪漂移 | 污染角度与朝向 | 无自动检测；靠人工复核 + R |

## 12. 未闭环部分（报告必须承认）

| 缺口 | 现状 |
|---|---|
| 手眼标定（眼在手/手在腕） | **未做** |
| 相机系 → 机器人基坐标系变换 | **未做** |
| 夹爪 TCP / 抓取坐标系 / 可达性 / 碰撞 | **未做** |
| 独立物理位姿真值（转台或治具） | **无**，所有精度数字都不能称"实物精度" |
| 混合三类模型的训练完成度 | 仅到两个训练视频自动处理完成，无全量完成与训练完成依据 |
| 自动重定位 | 已实现又回退，当前**不具备** |

**建议的下一步顺序**（成本从低到高）：

1. 固定相机 + 转台，采集 20~30 个已知角度，得到**第一份实物角度真值**；
2. 用该真值重评第 6、8 节的角度与位姿误差，替换掉"合成/一致性"口径；
3. 做眼在手外标定（棋盘格 + 机械臂点触 6~10 点），输出 `T_cam→base`；
4. 补 `pose_in_robot_base` 字段，先用 CAD + 关节限位做离线可达性验算，再上真机；
5. 最后才谈抓取成功率与失败分类。

## 13. 复现路径

本仓库归档的是**方案与证据**；原始工程代码（`pose_dataset/`、`rotation_pose/`、`ct_pose_capture/`、
`metal_video_annotations/`、`mixed_video_annotations/`）在视觉负责人的工作机上，未随仓库提交。
复现按下面的顺序，每一步都要有落盘产物：

```
① 采集       rgb.png / depth.png / cam_K.txt / camera.json          → 校验 depth_scale=0.001
② 标注       yolo_masks/metadata.json + 逐实例 PNG                  → GPU 峰值 ~610 MiB
③ 训练       CT_seg.pt（YOLOv8s-seg，22 ep 微调）                    → 选模看 mAP50-95(M)
④ 初始化     pose/{pose.txt, initialization.json, *_overlay.png}     → 检查 IoU 与外轮廓对齐
⑤ 跟踪       tracking_XX/summary.json（150 帧，14.5 Hz）             → 检查 P95 与帧数
⑥ 方向       rotation_pose/.../summary.json（415 帧）                → 检查拒识原因分布
```

环境相关：OpenCV 5.0.0、NumPy 2.5.4、Ultralytics（YOLOv8s-seg）、FoundationPose；
`metrics.json` 里带 `manifest_sha256` 与三个源文件 sha256，可用于核对是否同一份代码跑出来的。
